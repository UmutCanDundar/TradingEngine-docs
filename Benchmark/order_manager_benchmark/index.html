    Order Manager Benchmark

    Scenarios

    • Single — a single message processed in isolation; covers the minimal order manager path for that message type.
    • Flow — a sequence of related messages processed in order; for example FIX: NewOrder followed by ExecutionReport and Cancel. Reflects realistic message flow through the order manager.
    • Mixed Traffic — 3 messages per protocol interleaved in random order across all protocols and venues. Reflects realistic production traffic patterns where messages from different protocols arrive concurrently.

    Order Manager Dispatch — Mixed Traffic

    The dispatch benchmark processes a mixed sequence of messages from all protocols and venues through the order manager in a single thread.

    Order Manager Summary — Notes

    OUCH p999 anomaly. OUCH BIST and OUCH NQ show p999 values of 59k–80k cycles against p50 values of 210–326 cycles — a 200–380x ratio. FIX and ITCH p999/p50 ratios stay under 2x. OUCH order manager handles acknowledgement matching against a pending order table; occasional hash table probe depth variance or cache miss on the awaiting-ack lookup is the suspected cause of these tail spikes — not yet isolated. This warrants a dedicated follow-up test with hash table access instrumented separately.

    ITCH single is faster than FIX single. ITCH messages carry market data that follows a simpler order manager path — no awaiting-ack table lookup required. FIX single at 120 cycles includes the full ack-matching path.

    Flow cost is roughly 2x single across all protocols. Flow scenarios include both a new order and an execution report in sequence. The near-linear scaling confirms the order manager processes each message atomically in arrival order with no batching or reordering — minimal shared state overhead between consecutive messages.
